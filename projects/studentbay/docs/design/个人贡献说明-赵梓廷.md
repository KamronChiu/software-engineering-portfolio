## 3. 核心技术贡献

### 3.1 多卖家订单与单件库存一致性

针对校园二手商品“一件一库存”的特点，本人实现了：

1. 结算前重新校验商品是否仍为 `AVAILABLE`；
2. 按 `sellerId` 对购物车商品分组；
3. 每个卖家生成独立子订单；
4. 商品状态同步变为 `RESERVED`；
5. 订单项保存标题与成交价格快照；
6. 取消、超时或退款后按规则释放商品；
7. 完成交易后商品进入 `SOLD`。

这样既保留买家“一次结算”的体验，又确保不同卖家的履约和售后责任彼此独立。

### 3.2 校园面交创新流程

通用商城通常只处理快递，本项目额外完成校园面交闭环：

- 保存面交日期、起止时间和校园地点；
- 买卖双方均可提出修改，但必须由对方接受；
- 新时间与双方其他有效面交订单进行冲突检测；
- 买家取件码与卖家交付码相互独立；
- 卖家先验证买家码确认交付，买家再验证卖家码确认收货；
- 订单详情用 Meeting 卡片和时间线呈现当前步骤。

双向码避免单方误触完成，协商记录避免口头约定无法追踪，是 StudentBay 区别于普通 CRUD 项目的重要创新。

### 3.3 支付可靠性与风险控制

本人完成支付安全链路：

- 模拟支付的处理中与成功反馈；
- 每张子订单独立幂等键；
- 相同幂等键重复请求返回同一结果；
- 不同幂等键对已付款订单返回冲突；
- 数据库悲观锁保护并发支付；
- 支付超时自动取消并释放商品、金币和优惠券；
- 支付宝异步通知验签、交易状态二次查询和金额核对；
- 大额交易、频繁取消、异常改价与低信用交易对象提示。

### 3.4 正式售后与平台治理

本人将简单退款按钮扩展为可追踪工单：

```text
买家申请 → 卖家审核 → 协商结果 → 平台介入 → 管理员审核 → 执行退款
```

规则包括付款后即可申请、确认收货 7 天后关闭入口、工单唯一、状态可追溯、退款后释放商品。Day9 进一步把售后事件写入聊天会话，使卖家获得未读提醒，并通过订单锁、服务端状态校验和页面刷新解决买卖双方状态不同步问题。

### 3.5 智能搜索与可解释降级

自然语言搜索支持预算、品类、成色、关键词和面交偏好。本人采用“AI 解析 + 本地确定性检索”的方式：

- AI 服务可用时解析复杂表达；
- 未配置、超时或失败时使用本地语义规则；
- 最终商品只能来自本地数据库，AI 不虚构库存；
- 对“儿童玩具”等其他类商品扩展积木、拼图、玩偶、毛绒、遥控车和磁力片同义词；
- 明确商品意图时必须命中标题或描述，避免折叠伞因同属“其他”而被错误推荐。

### 3.6 用户体验与运营能力

- 商品详情、订单、支付和售后均使用业务含义明确的层级与动效；
- 页面支持浅色/深色、移动端和 `prefers-reduced-motion`；
- 装饰层不拦截点击，提交按钮在请求期间禁用；
- 价格保护展示校内均价与偏差，不伪造市场数据；
- 管理员看板提供日期筛选、订单趋势、状态结构、分类成交和治理队列；
- 任务、金币和掷骰子寻宝增强平台持续使用动力。

1. **业务完整性**：正常交易与异常售后都有明确下一步；
