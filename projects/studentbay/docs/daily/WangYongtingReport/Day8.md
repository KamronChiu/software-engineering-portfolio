## 今日目标

在 Day 5 我的空间（宝贝 / 评价 / 动态三面板）与 Day 4 双向评价体系之上，把"信用"沉淀为可量化的数字：为每个用户分别评定**买家信用**与**卖家信用**，综合成交订单、收到的双向好评与商品被举报情况给出 0-100 的信用分和四档信用等级，并落进我的空间页面形成可视化面板，让交易双方在沟通与下单前能直观判断对方的可信度。同时把平台需求整理成正式的需求说明书文档，沉淀范围、角色、业务流程与验收口径。

## 今日完成内容

### 1. 信用模型与指标口径

- 定义两个独立评分维度：**卖家信用**（面向我作为卖家卖出商品的行为）与**买家信用**（面向我作为买家买进商品的行为），二者分别计算、互不影响。
- 信用构成指标统一从现有业务数据实时统计，口径如下：
  - 卖出商品数：作为卖家完成（`COMPLETED`）的订单数；
  - 买进商品数：作为买家完成（`COMPLETED`）的订单数；
  - 好评数：收到的双向评价中星级 ≥ 4 的数量（卖家信用取"买家评价我"，买家信用取"卖家评价我"）；
  - 商品被举报数：我发布的全部商品被举报的总数。
- 信用分计算公式：基准 50 分，成功交易每笔 +6（上限 +30）、好评每条 +6（上限 +30）、商品被举报每条 −12（上限 −36），总分截断在 0-100 并四舍五入取整。
- 按分值划分四档等级：≥85 为"非常可信"，≥70 为"信用良好"，≥55 为"信用正常"，其余为"建议谨慎交易"。

### 2. 信用服务与接口

- 新增 `SpaceCreditService`（trust 包）：以只读事务聚合订单、评价、商品与举报四类数据完成上述统计，返回信用分、等级标签、全部构成指标与规则说明文案。
- 新增 `SpaceCreditController`：提供 `GET /api/space/credit`，基于会话获取当前用户并返回其信用档案，供我的空间页面加载。
- 仓储层补齐聚合查询：`OrderRepository` 增加按卖家 / 买家 + 订单状态计数的方法；`ReportRepository` 增加按商品 ID 集合统计举报数的方法，避免逐条循环计数。

### 3. 我的空间信用面板

- 我的空间页面（宝贝 / 评价 / 动态三面板之上）新增"我的信用"卡片区：
  - 顶部标题区说明"买家信用与卖家信用分别评定，点击卡片查看构成明细与评定规则"；
  - 两张信用卡片并列展示买家信用与卖家信用：大字信用分、按分值着色的进度条与当前等级文案；
  - 点击任意卡片展开构成明细：卖出商品数、买进商品数、卖家好评、买家好评与商品被举报数五项指标，并展示完整评定规则；
  - 明细区可关闭，再次点击卡片可重新展开，卡片间互斥切换。
- 前端新增 `loadSpaceCredit`：页面加载时请求 `/api/space/credit` 并渲染分数、等级与指标；接口异常或未登录时保持"计算中"占位，不影响页面其它区域。

### 4. 样式适配

## Day 8 总结

Day 8 为平台补上了可量化的信用表达：卖家信用与买家信用分开评定，口径全部取自真实业务数据——完成的订单证明交易意愿，双向好评证明履约口碑，商品被举报记录则作为风险扣分项；0-100 的信用分配以"非常可信 / 信用良好 / 信用正常 / 建议谨慎交易"四档等级，直白可读。我的空间页面的信用面板让用户随时看到自己的信用构成，也为后续在商品详情、聊天与订单环节展示对方信用留好了数据接口。需求说明书的整理则把两个月来散落在各页面与接口里的规则收敛成一份可供追溯与验收的文档，与代码实现互相印证。
