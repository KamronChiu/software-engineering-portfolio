## 今日完成内容

### 1. 问题定位与根因分析

- **现象**：发布页地图区域无法显示地图（灰块）、地图相关控件与布局错乱（乱码感）；商品无法正常发布。
- **根因一（主因）**：`publish.html`、`product-detail.html` 中 Leaflet 样式表的 SRI `integrity` 哈希写错，浏览器整块拒绝加载 `leaflet.css`。
  - 页面声明哈希与 CDN 实际返回字节的 SHA-256 不一致（已用多个 CDN 实测比对确认）；
  - 浏览器控制台实测报错：`Failed to find a valid digest in the 'integrity' attribute ... The resource has been blocked.`
  - 后果链：Leaflet 样式未生效 → 地图容器内 `.leaflet-*` 元素无样式、布局错乱 → 用户无法在地图上完成选点 → 发布提交被"请在地图上选择交易位置"拦截 → **无法发布**。
  - 注：`leaflet.js` 的哈希经核对是正确的，问题只在 CSS。
- **根因二**：地图瓦片源 `tile.openstreetmap.org` 在国内网络下不可达（实测超时），即使样式修复地图仍会空白灰屏。
- **附带风险**：原 CDN `unpkg.com` 在国内访问不稳定，影响地图库加载。

### 2. 更正 Leaflet CSS 的 SRI 哈希

- 将 `leaflet.css` 的 `integrity` 更新为与 CDN 实际字节一致的哈希：`sha256-p4NxAoJBhIIN+hmNHrzRCf9tD/miZyoHS5obTRR9BMY=`，确保样式正确加载。

### 3. Leaflet 引入地址由 unpkg 切换至 jsdelivr

- 将 `publish.html`、`product-detail.html` 中 Leaflet CSS/JS 引入地址由 `unpkg.com` 切换至 `cdn.jsdelivr.net`（版本仍为 1.9.4，JS 哈希不变，已验证两 CDN 字节一致、哈希通用），提升国内访问稳定性。

### 4. 默认地图瓦片源切换为高德地图

- 将 `DemoDataInitializer` 中默认瓦片源由 OpenStreetMap 改为高德瓦片：`https://webrd01.is.autonavi.com/appmaptile?...&x={x}&y={y}&z={z}`，版权标注同步为「© 高德地图」。
- 高德瓦片已实测可用（HTTP 200、image/png、响应快），解决国内网络下地图无法加载的问题。

### 5. 数据初始化新增自愈逻辑

- 在 `DemoDataInitializer` 中新增 `repairLegacyTileUrl()`：当数据库 `app_config` 中 `map.tileUrl` 仍是旧的 OSM 地址时，自动更新为高德地址，避免老库不生效，保证现有部署重启即修复。
