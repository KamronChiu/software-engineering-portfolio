## 今日目标

在不改变 StudentBay 原有商品、购物车、收藏、咨询、举报和订单接口能力的基础上，完善校园交易的线下面交流程和支付反馈，修正多卖家购物车的订单拆分逻辑，并为管理员提供基于真实数据库数据的运营可视化面板。同时完成校园网内部访问配置，集成组员新增的登录注册功能，补充覆盖全部商品分类的演示数据，并建立可重复运行的业务流程与 Web 页面自动化测试体系。

## 今日完成内容

### 1. 校园网内部访问与部署准备

- 将 Spring Boot 监听地址配置为 `0.0.0.0`，允许同一校园网络中的其他设备访问。
- 保留 `SERVER_ADDRESS` 和 `SERVER_PORT` 环境变量覆盖能力，方便不同电脑和端口部署。
- 增加校园网启动脚本，统一数据库密码、监听地址和端口的启动方式。
- 在项目 README 中补充 macOS 防火墙、校园网客户端隔离、IP 地址查询和访问地址说明。
- 确认访问形式为 `http://校园网IP:8080`，当前 IP 变化后可重新查询并通知访问者。

### 2. 购物车按卖家拆分订单

- 保留买家视角的一次购物车结算体验。
- 结算提交后按照 `sellerId` 对商品进行分组。
- 同一卖家的多件商品合并到一张子订单，不同卖家生成不同子订单。
- 配送费由原来的按商品数量计算调整为按卖家子订单计算，避免同一卖家的多件商品重复收取运费。
- 结算页明确展示卖家数量和支付后生成的子订单数量。
- 优惠券资格改为按照卖家子订单金额判断，与后端订单金额保持一致。
- 保留金币抵扣和多件购买奖励券逻辑。

### 3. 校园面交预约信息

- 用户选择“校内自提”后显示独立的 Meeting 面交区域。
- 支持选择面交日期、开始时间、结束时间和校园地点。
- 默认时间设置为 `17:30-18:00`。
- 默认地点优先使用商品发布时填写的校园位置，也可以由买家修改。
- 订单保存面交开始时间、结束时间和地点，订单详情页可以持续展示。
- 后端校验结束时间必须晚于开始时间，避免保存无效时间段。

### 4. 双向取件码

- 每张校园面交订单分别生成买家取件码和卖家交付码。
- 买家只能看到自己的取件码，并在面交时向卖家出示。
- 卖家只能看到自己的交付码，并在面交时向买家出示。
- 卖家输入买家取件码并验证成功后，订单进入已交付状态。
- 买家验货后输入卖家交付码，验证成功后订单进入已完成状态。
- 错误或缺失的取件码会返回明确提示，不会推进订单状态。
- 为已有历史面交订单提供兼容取件码，避免数据库升级后旧订单页面无法显示。

### 5. 订单详情时间线

- 将订单详情顶部的横向步骤改为纵向交易时间线。
- 快递订单展示订单创建、支付完成、快递预约、运输和交易完成节点。
- 面交订单展示订单创建、面交确认、卖家交付和双方确认节点。
- 当前节点、已完成节点和待进行节点使用不同视觉层级。
- 面交订单增加独立 Meeting 卡片，展示 Today、时间段、地点和当前用户取件码。
- 金额、配送信息、商品快照和更多服务入口继续保留。
- 订单金额栏在桌面端保持悬浮，移动端自动回到正常文档流，避免遮挡按钮。

### 6. 结算价格保护提示

- 结算页新增 Price Protection 价格保护区域。
- 调用现有同类商品价格对照接口读取真实挂牌数据。
- 展示商品市场均价、当前价格以及相对均价的差异百分比。
- 低于均价时显示绿色提示，高于均价时显示风险提醒。
- 样本不足时显示中性提示，不生成虚假的市场均价。
- 明确说明数据来自校内挂牌价，只用于交易判断参考。

### 7. 模拟支付体验

- 将原有简单支付卡片升级为分屏式 StudentBay Pay 页面。
- 支付页列出每张卖家子订单、卖家编号、商品和金额。
- 用户点击确认支付后立即显示 `Processing payment...`。
- 支付接口完成且至少等待 0.8 秒后显示 `✓ Payment successful`。
- 支付过程中按钮保持禁用，避免重复点击和重复请求。
- 支付失败时恢复按钮并显示错误信息，用户可以重新尝试。
- 支付成功后展示本次完成支付的卖家子订单数量。

### 8. 支付成功动画

- 支付成功页面新增 check 弹出动画和外圈展开动画。
- 动画仅使用 `transform` 和 `opacity`，降低页面重绘开销。
- 保留查看订单、进入任务中心和继续浏览等原有入口。
- 在 `prefers-reduced-motion` 模式下关闭动画，保证无障碍体验。

### 9. 管理员数据可视化面板

- 展示投诉举报、退款订单和需要平台介入的异常订单数量。
- 展示正常、停用和已认证用户数量及用户健康度。

## 遇到的问题与解决方案

| 问题 | 解决方案 |
|---|---|
| 购物车每件商品都会生成一张订单 | 先按 `sellerId` 分组，再为每位卖家创建一张包含多个商品快照的子订单 |
| 配送费按照商品件数重复计算 | 改为按照卖家子订单数量计算配送费 |
| 面交只有简单确认，缺少双方凭证 | 为买卖双方分别生成取件码，并在两个确认节点进行服务端校验 |
| 历史订单没有新的面交字段 | 对历史面交订单提供页面回退信息和兼容取件码 |
| 结算前无法判断价格是否合理 | 复用同类商品价格对照接口，在提交订单前显示真实均价差异 |
| 支付状态反馈过快且缺少层次 | 增加处理中、成功和失败状态，并设置 0.8 秒最低反馈时间 |
| 管理后台只有数据表格 | 增加数据库实时统计接口和订单趋势、状态分布、治理队列可视化 |
| 移动端订单编号与状态编号产生横向溢出 | 在小屏幕下调整订单头部网格和长文本换行规则 |
| 集成测试在沙箱内无法绑定随机端口 | 将订单测试迁移到 MockMvc，保留完整 Spring 业务链路并消除端口依赖 |
| 已有数据库不会执行 `products.count() == 0` 分支 | 将初始化调整为按稳定标题增量补齐，保留已有用户商品并避免重复插入 |
| HTML5 页面无法作为严格 XML 运行 XPath 检查 | Web 页面测试改为验证响应、脚本引用和关键 DOM 标识，兼容现有 HTML5 模板 |
